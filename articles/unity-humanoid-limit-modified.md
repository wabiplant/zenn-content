アニメーションは再生されているのに、キャラクターの体がほとんど動かない。前に進み、手足の先はそれらしく動くのに、腰のひねりも体の傾きも消えていて、マネキンが滑っているように見える。侍100人斬りライトのキャラクターで実際に起きた症状です。

結論から書くと、犯人はモーションでもモデルでもなく、FBX の `.meta` ファイルに残っていた `limit` の `modified: 1` でした。直し方は `.meta` のテキスト編集だけで、FBX の書き出し直しは要りません。

## 切り分け:Generic では動く

最初に疑ったのはモーションの作り直し不足でした。ただ、同じ FBX を Rig の Animation Type を **Generic** に変えて読み直すと、原画どおりに体全体が動きます。つまりクリップにもモデルにも問題はなく、おかしいのは **Humanoid への変換だけ** です。

次に、正常に動いている別のキャラクター（弁慶）の `.meta` と、動かない側の `.meta` を見比べました。そこで違っていたのが、`human` 配列の中にある各ボーンの `limit` の `modified` フラグです。正常な側は `modified: 0`、動かない側は軒並み `modified: 1` になっていました。

## 原因:値がゼロでも modified: 1 が残ると筋肉カーブが全ゼロになる

`.meta` の中では、Humanoid の各ボーンについて、筋肉（Muscle）の制限が次のような形で保存されています。

```yaml
limit:
  min: {x: 0, y: 0, z: 0}
  max: {x: 0, y: 0, z: 0}
  value: {x: 0, y: 0, z: 0}
  modified: 1
```

ここで `min` / `max` / `value` が全部ゼロでも、`modified: 1` が残っていると、Unity の Humanoid 変換はそのボーンの筋肉カーブをゼロとして扱います。これが全ボーン分そろうと、変換後のアニメーションからは体の動きがほぼ消え、ルートの移動と手足の到達だけが残ります。プレビューの症状とぴったり一致しました。

やっかいなのは見た目です。制限値を触った覚えがなくても、Avatar の設定画面を開いたり、修復スクリプトを通したりした拍子にフラグだけが残ることがあります。値がゼロに清書されているので、一見すると「制限は無効化されている」ように見えます。

## 直し方:modified: 0 に戻す

修復はシンプルです。

1. FBX の `.meta` をテキストエディタで開く
2. `human` 配列の各ボーンについて、`limit` の `modified: 1` を `modified: 0` に書き換える
3. Unity で再インポートする

ポイントは、**limit の値をゼロに清書するだけでは直らない** ことです。直す対象は値ではなくフラグの方で、`modified: 0` へ戻すこと自体が修復になります。再インポート後にプレビューで確認すると、体のひねりや傾きが戻っていました。FBX 本体には一切触っていません。

## ついでに踏んだ注意点

- **正常な資産でも、再インポートで壊れることがある。** 変換が正常に済んでいるモーション資産でも、`.meta` に `modified: 1` が残っていると、再インポートした瞬間に同じ症状が出ます。実際に別のモーション資産で踏みました。「前は動いていたのに、触っていないのに壊れた」という場合はここを疑う価値があります。
- **アバターを触るスクリプトは、フラグを落とすところまでが仕事。** Avatar 関連の修復・変換スクリプトを書くときは、limit の値をいじるだけでなく、`modified` フラグを必ず落とすようにしておくと再発しません。

## まとめ

「アニメーションは再生されるのに体が動かない」「Generic では原画どおり動く」――この2つがそろったら、モーションを作り直す前に `.meta` の `limit.modified` を確認してみてください。テキスト編集と再インポートだけで直ることがあります。
